  .\RUN.ps1                     uruchom aktualne źródła

  .\FORMAT.ps1 -Check           sprawdź styl bez zapisywania zmian
  .\BAKE-HIT-MASKS.ps1           przelicz maski po zmianie ilustracji/klatek
  .\TEST.ps1 -Suite Architecture składnia, zależności i granice modułów
  .\TEST.ps1 -Suite Mechanics    mechanika, zasoby i kontrakty aplikacji
  .\TEST.ps1 -Suite Input        prawdziwe callbacki, menu i zapis
  .\TEST.ps1 -Suite Render       widoki gry i pomiary interfejsu
  .\TEST.ps1                     wszystkie powyższe kontrole

Pełny Render obejmuje także gęste próbkowanie trafień w żywych animacjach.
Na wolniejszym komputerze można jawnie zwiększyć limit procesu, bez pomijania
próbek: .\TEST.ps1 -Suite Render -TestTimeoutSeconds 1200.
Analogiczny parametr ma tools/verify.ps1. Limit domyślny wynosi 300 sekund;
timeout nie jest zaliczonym testem. Przebieg trafień wypisuje kolejne archetypy.
  .\BUILD.ps1                    testy, snapshot, testy EXE, weryfikowany ZIP

Po udanych testach źródeł można wykonać samo tools/build.ps1, a potem
tools/verify.ps1. Drugi krok jest konieczny do poświadczenia i utworzenia ZIP.
Testy są wyciszone, poza ekranem, bez przejmowania myszy i na osobnym zapisie.
Główne raporty zapisują się w work/qa-v<wersja> (qaOutput w release.lua;
numer wersji: game/src/core/build.lua, czytany też przez tools/project.ps1).
Jeden zestaw testów: lovec.exe game --selftest --suite=<id> (id z
tests/suite.lua); raport suite-<id>-results.txt nie nadpisuje pełnego
test-results.txt. Błąd jednego zestawu przerywa pełny przebieg.
Pomiary rdzenia (0.29, każdy osobno, raport w work/qa-v<wersja>):
  --core-measure   maski (start, pamięć), salwa, pociski, pazur, Snapshot,
                   Journal, długa sesja -> core-measure.txt
  --step-study     ten sam przebieg przy różnym FPS oraz różnym kroku
                   symulacji (prawa ruchu i kontaktu) -> step-study.txt
  --mask-formats   formaty masek (hex, przycięte, upakowane, RLE): rozmiar,
                   wczytanie, dekodowanie -> mask-formats.txt
  --pigment-review skok i unik obok modelu bazowego, przed/po w tym samym
                   świetle; alfa 16 klatek -> creature-pigment.txt, pigment-*.png
Balans: --population liczy same populacje botów (raport playtest-population).
Trafienia: --hit-review liczy same raporty trafień względem obrazu (hit-*,
plan v7 H0–H9). Nowy punkt anatomiczny: wycinek tools/art/landmarks/crops.ps1,
wpis w game/qa/data/hit_landmarks.lua, test hit-landmarks sprawdzi, czy leży
na pigmencie lub w powietrzu tak, jak gra go rysuje.
Zmiana numeru wersji wymaga też utworzenia odpowiadającego docs/ZMIANY-X.txt.
Do uruchamiania i testowania wystarcza dołączony runtime; Node/Python nie są
zależnościami projektu. StyLua jest dołączonym narzędziem deweloperskim.

  docs/ANATOMIA-I-FIZYKA-0.28.txt. Liczba kończyn nie jest stałą silnika.

Wyposażenie i nowe rodzaje dostawy:

  Nowy rodzaj: Action.defineKind opisuje jego schemat; moduł zachowania
  zwraca funkcję (g, ability), rejestrowaną przy starcie jako
  Cast.kinds[id] = require('src.combat.<moduł>'). Treść nie importuje combat.

  sam nowy damageType nie nadaje pociskowi statusu. Nie dodawaj ifów po ID
